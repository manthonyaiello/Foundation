AES Spec Crosswalk

NSA's Cryptol for AES (algorithms/AES/*.cry) and our SPARK spec layer (spark/src/aes/foundation_spark-aes-spec-*.ads), definition by definition. Each pair is copied verbatim from the files, with comments removed. Where the two differ, the page says why.

The goal was minimal syntactic and semantic distance, so a person can check one against the other by eye. Read top to bottom. The primer and the AES recap come first, then the six modules in dependency order, then the properties, the SPARKlib question, and how the match is checked by machine.

Verdict

The specs match closely. Every Cryptol definition that AES uses has a SPARK counterpart with the same name, the same arguments in the same order, and a body of the same shape. The S-box, inverse S-box and round-constant tables are identical entry for entry; I checked that with a script while writing this page. The deviations have four causes, all listed in one table:

  • Ada can't spell it. There's no • operator, no ' in names, and in and reverse are reserved words.
  • Cryptol built-ins have no Cryptol body. pmult, pmod, pdiv, foldl, split/join and @@ are written out in SPARK. This is the largest real semantic addition.
  • Ada has no type-level numbers. The key size k becomes the formal K of a generic package, and AES`{128} becomes an instance. Only two traces remain: Key k is a list of values, and ghost dispatchers let the implementation pick an instance at run time.
  • Structural rewrites. A self-referential list becomes a recursive function. A list pattern becomes slices. A record of functions becomes a generic package. One undefined table entry is dropped.
Same

Identical structure and operators. Only Ada's surface syntax differs (A (I) for a@i, xor for ^).

Spelling

Same meaning, but a name or form had to change because Ada can't express the Cryptol one.

Deviation

The SPARK is shaped differently or says more. Each one is explained where it occurs.

On the SPARK side, almost everything is an expression function, function F (…) return T is (expr), which is as close to a Cryptol equation as Ada gets. [for I in R => e] builds an array. Ghost marks code that exists only for proof and never reaches the executable. Subprogram_Variant gives a recursive function a decreasing measure, so the prover knows it terminates.

AES in brief

AES encrypts one 16-byte block under a 128-, 192- or 256-bit key. The key length sets two numbers: Nk, the key's length in 32-bit words (4, 6 or 8), and Nr, the number of rounds (10, 12 or 14).

KeyExpansion stretches the key into Nr + 1 round keys, one block each. Cipher then works on the block, called the state and read as a 4×4 byte matrix stored column by column:

AddRoundKey w₀→ Round × (Nr−1): SubBytes → ShiftRows → MixColumns → AddRoundKey wᵢ→ SubBytes → ShiftRows → AddRoundKey w_Nr
  • SubBytes replaces every byte through a fixed 256-entry table, the S-box.
  • ShiftRows rotates row r of the matrix left by r places. With column-major storage, that is a fixed permutation of the 16 byte positions.
  • MixColumns multiplies each column by a fixed 4×4 matrix. The arithmetic is in GF(2⁸): addition is XOR, and multiplication (•) is polynomial multiplication modulo x⁸+x⁴+x³+x+1.
  • AddRoundKey XORs in the round key.

The last round skips MixColumns. InvCipher runs the inverse steps with the round keys in reverse order.

-- Spec.Dispatch: SPARK only
procedure Lemma_Key_Size (K : Natural)
with
  Post =>
    (K in Key_Size)
    = (K mod 64 = 0 and then K / 64 >= 2 and then K / 64 <= 4);

function Cipher (K : Key_Size; W : Round_Keys; Input : Block) return Block
is (case K is
      when 128 => AES128.Cipher (W, Input),
      when 192 => AES192.Cipher (W, Input),
      when 256 => AES256.Cipher (W, Input))
with
  Pre  => Is_Round_Keys (K, W),
  Post =>
    Cipher'Result
    = AddRoundKey (ShiftRows (SubBytes
                     (Foldl_Round (AddRoundKey (Input, W (0)),
                                   W (1 .. Nr (K) - 1)))),
                   W (Nr (K)));
Why. Cryptol's {k} functions (KeyExpansion with its w, Cipher, InvCipher, InvCipher', and Main.cry's record AES`{k}) are the generic package Spec.AES_K. Its formal K is the Cryptol's k, and its subtype Key_Size is the constraint Key k. The library-level instances Spec.AES128, AES192 and AES256 are Main.cry's AES128 = AES`{128} and so on. Inside the generic, the lengths are in subtypes: Key_Words (0 .. Nk - 1) is [Nk k]AESWord, Round_Keys (0 .. Nr) is [Nr k + 1]Block, and Key_Bits (0 .. K - 1) is [k]. So each function takes the Cryptol's arguments, with no K argument and no precondition. Everything without a {k} is not generic and is proved once. The generic reads the constants Nk and Nr rather than calling Types.Nk (K), because GNAT 16.1 crashes on that call inside an instance's expression function. KeyExpansion.cry has the same local Nk = `(Nk k).

Two things remain that the Cryptol doesn't have. (1) Key_Size lists the values 128 | 192 | 256 instead of stating Types.cry's clauses. It must be a Static_Predicate, because a Pure instance needs static bounds for its subtypes, and a static predicate can't use mod. Dispatch.Lemma_Key_Size proves the list equal to the clauses, clause for clause. (2) Spec.Dispatch holds one ghost dispatcher per {k} function, which selects the instance by a run-time K. Each dispatcher's postcondition states the Cryptol body uniformly in K. The implementation serves all three key sizes with one body, so it takes K : Key_Size explicitly, with Is_Key_Words/Is_Round_Keys preconditions, and its postconditions name the dispatchers. That explicit K is also the shape Cryptol's FFI uses for foreign functions: a numeric type parameter arrives as a leading size_t. Spike #74 measured no change in proof wall-clock for the generic (PR #78), and #80 carried it out.

Why. Cryptol's pmult and pmod have no definition in Cryptol, so there is nothing to mirror. SPARK has to state what they mean. It does so as schoolbook shift-and-XOR multiplication and long division, one bit per step, most significant bit first (Cryptol's order). It states them only at the sizes AES uses: [8]×[8]→[15] and [15] mod [9]→[8]. This is the one place where the SPARK carries meaning that a reader can't check against Cryptol text. It is checked against Cryptol's behavior instead: Dot is tested exhaustively against (•) over the FFI, and SAW proves the spec layer equal to the Cryptol. GF28.cry's own property GF28MultiplicationCorrect, also proved in SPARK, ties Dot to xTimes and a fold.

function Affine_Bit (Inv : Types.Byte; I : GF28.Bit_Index) return Boolean

    xor Reversed_Bit (Inv, (I + 4) mod 8)
    xor Reversed_Bit (Inv, (I + 5) mod 8)
    xor Reversed_Bit (Inv, (I + 6) mod 8)
    xor Reversed_Bit (Inv, (I + 7) mod 8)

function Affine (B : Types.Byte) return Types.Byte
is ((if Affine_Bit (GF2.Inverse (B, SBoxPolynomial), 0) then 16#01#
     else 0)
    or (if Affine_Bit (GF2.Inverse (B, SBoxPolynomial), 1) then 16#02#
        else 0)
    …
    or (if Affine_Bit (GF2.Inverse (B, SBoxPolynomial), 7) then 16#80#

Why. The bit equation Affine_Bit matches Cryptol's b'@i term for term. What changes is the reversals. Cryptol reverses the byte, works on bit i, then reverses back. With bytes as integers, SPARK reads "bit i of the reversed byte" directly (Reversed_Bit). It undoes the final reverse b' by giving b'@i the value 2i (16#01# for i = 0 … 16#80# for i = 7). To check it, confirm that reverse sends Cryptol index i to 7 − i, which is the bit worth 2i. 0b01100011 is 16#63#. None of this reaches the cipher, which reads the table. affine exists only for the property SBoxCorrect (S-box = affine, entry by entry), which SPARK proves by evaluating all 256 entries.

SPARKspec-aes_k.ads:41–84
Nk : constant Positive := Types.Nk (K);

subtype Word_Index is Natural range 0 .. 4 * (Nr + 1) - 1;

is (if I < Nk then Key (I)
    elsif I mod Nk = 0
    then W (Key, I - Nk) xor SubWord (RotWord (W (Key, I - 1)))
         xor Rcon (I / Nk)
    elsif I mod Nk = 4 and then Nk > 6
    then W (Key, I - Nk) xor SubWord (W (Key, I - 1))
    else W (Key, I - Nk) xor W (Key, I - 1))
with Subprogram_Variant => (Decreases => I);

is [for R in 0 .. Nr => Join ([for J in AESWord_Index =>
                                     W (Key, 4 * R + J)])];
Why. Cryptol defines w as a list whose elements refer to earlier elements of the same list, which works because Cryptol is lazy. Ada can't define a value in terms of itself, so w@i becomes the recursive function W (Key, I) in the generic AES_K. Its four cases are copied line for line, and read as the Cryptol does: I < Nk, I mod Nk = 0, W (Key, I - Nk). Nk is a constant of the generic, as it is a local of KeyExpansion.cry. Decreases => I records that each case looks only backwards. The comprehension's range i <- [0 ..< 4 * (Nr k + 1)] becomes the subtype Word_Index, so W has no precondition. split (split (join (join w))) only regroups the words: it flattens 4(Nr+1) words to bytes and cuts them back into Nr+1 blocks. SPARK states the effect directly: round key R is the four words 4R … 4R+3, joined. That regrouping is the one line here that a reader has to check by reasoning, not by matching text.

@@ (gather) becomes an array built from indices. The index lists are the same numbers in the same layout, moved into a named constant. SBox @@ bs means "look up each byte of bs in SBox", which is exactly the SPARK aggregate.

Read the coefficient matrices row by row: they're the same 16 constants in the same positions. map f xs becomes an array built over the four columns. Cryptol's bs ^ w XORs two blocks byte by byte, and SPARK spells that out.

The composition order is identical. Ada names can't contain ', so X' becomes X_Prime. InvRound is FIPS-197's "equivalent inverse cipher" round. InvRound' is the literal inverse of Round, which NSA kept for the property RoundInverts.

Cipher and InvCipher Deviation

CryptolCipher.cry:24–61
foreign Cipher : {k} (Key k) => [Nr k + 1]Block -> Block -> Block
Cipher ([w0] # ws # [wr]) in = state_final
  where
    state_initial    = AddRoundKey in w0
    state_rounds     = foldl Round state_initial ws
    state_final      = AddRoundKey (ShiftRows (SubBytes state_rounds)) wr

foreign InvCipher : {k} (Key k) => [Nr k + 1]Block -> Block -> Block
InvCipher ([w0] # ws # [wr]) in = state_final
  where
    state_initial    = AddRoundKey in wr
    state_rounds     = foldl InvRound state_initial (reverse ws)
    state_final      = AddRoundKey (InvSubBytes (InvShiftRows state_rounds)) w0

Why. Cipher, InvCipher and InvCipher' are {k} functions, so they are in the generic AES_K, with the Cryptol's two arguments. The folds, Reverse_Keys and the rounds have no {k}, so they stay in Spec.Cipher and are proved once. Beyond that, there are four small moves, all mechanical. (1) foldl is a Cryptol built-in, so each use becomes a recursive ghost function with the prelude's definition: foldl f z [] = z and foldl f z ([x] # xs) = foldl f (f z x) xs. There is one per round function (Foldl_Round, Foldl_InvRound, Foldl_InvRound_Prime), because a SPARK ghost function can't take a function as an argument without a generic. (2) The pattern [w0] # ws # [wr] becomes W (0), W (1 .. Nr - 1) and W (Nr). That is exact because the subtype Round_Keys (0 .. Nr) fixes W'First = 0 and W'Last = Nr. (3) The three where steps are nested into one expression. To read it, start at the innermost call and work outwards: state_initial, then state_rounds, then state_final. (4) in and reverse are Ada reserved words, so they become Input and Reverse_Keys. InvCipher' (InvCipher_Prime) follows the same pattern.

Why. Here the Cryptol types are bit strings of arbitrary length ([k], [128]), not bytes. Following the bit-sequence decision, SPARK models them as ghost Boolean arrays, with element 0 as the first (most significant) bit. The three conversions, Split_Key, Split_Block and Join_Block, are Cryptol's split/join at these types, written out with explicit big-endian bit packing (Byte_At, Bit_Of). Split_Key depends on k, so it is in the generic with Encrypt and Decrypt; the rest stays in Spec.Main. Cryptol's record of two functions has no SPARK counterpart, so the record AES`{k} is the generic AES_K, and Main.cry's AES128 = AES`{128} is the instance Spec.AES128: AES128.Encrypt is Main.cry's AES128.Encrypt. The call chain inside Encrypt is the Cryptol one, token for token, with no K argument. Bit_Index is now range 0 .. 256 (#68): the longest AES bit string is a 256-bit key, so its indices are 0 … 255 and its length 256. Index arithmetic is proved free of overflow in this range, following your 2026-10-20 ruling that wide types are not a way to avoid that proof. The narrower index also retires the gep64 rewrite that SAW needed for the 128-bit one (unverified until the next SAW session).

Properties

Each Cryptol property becomes a ghost procedure of the same name in foundation_spark-aes-spec-properties.ads. Its parameters are the property's arguments, and its Post is the property's body. gnatprove proves each one for all inputs and all three key sizes. A typical pair is below.

These proofs are optional. SAW proves the spec layer equal to the Cryptol, so the Cryptol's properties already hold of the SPARK spec. In general, re-proving the properties of a higher-level spec after moving to SPARK adds proof cost without adding a theorem. SBoxCorrect is the extreme case: it takes 26 minutes, for a closed property that Cryptol evaluates in under a second. They are kept for now because SAW runs only locally. Until it runs in CI, these properties are the continuously checked cross-check on the SPARK spec.

Where is SPARKlib used?

It isn't, and it is no longer a dependency. It was removed in #72. The dependency dated from the crate scaffolding (commit a24edbf, 2026-10-16), whose message says it was added "for SPARK.Higher_Order.Fold and SPARK.Big_Integers". Neither was ever used, and the page shows why:

  • Folds. The spec mirrors each foldl with its own recursive ghost function (Foldl_Round, Pmult_Fold, …) that states the Cryptol prelude's definition directly. That is closer to the Cryptol than a SPARKlib generic would be.
  • Big integers. Bit-string indices use a small fixed integer type, Bit_Index (range 0 .. 256), instead.

spark/README.md now says that SPARKlib, once a dependency, was never used and was removed (#72).

How the match is checked by machine

Reading this page is the human check. Three machine checks back it:

  • FFI testing (spec = Cryptol, by testing). Each ghost spec function is exported through C and called from Cryptol with foreign. Equivalence properties then run with :exhaust where the input space allows (e.g. Dot over all 216 pairs) and :check otherwise. This runs in CI.
  • SAW (spec = Cryptol, by proof). The spec layer is compiled to LLVM bitcode with ghost code enabled, and SAW proves it equal to NSA's Cryptol at k = 128, 192 and 256 with nothing assumed (spark/saw/results.txt). This covers the written-out primitives (pmult, pmod, the folds), the one place where text-matching alone can't settle the question. It runs locally only, because it needs GNAT Pro's LLVM back end. On this branch the SAW scripts name the instances (AES128.Cipher and so on, with no K argument), but they have not been rerun since #68 and #80, so results.txt still records the earlier spec layer.
  • gnatprove (implementation = spec). The executable AES is proved equal to this spec layer for every input. The spec's own Pres, variants and properties are proved too.
