AES Spec Before and After

Foundation's AES SPARK spec layer as you reviewed it against the Cryptol (3c956c1, the tree behind the published crosswalk of 2026-10-20) and as it is on main now (4431a75). Old SPARK on the left, new SPARK on the right, definition by definition.

The sections follow the crosswalk's order (Types, GF28, SBox, KeyExpansion, Cipher, Main, Properties), so the two pages can be read side by side. Then come the units that have no "before": the generic AES_K and its instances, Dispatch, and the Cryptol prelude in SPARK. Excerpts are copied from the named commit with comments removed (except the Folds unit, shown in full) and trimmed with …. Highlighted lines are the ones that differ. The Cryptol (algorithms/AES/*.cry) did not change between the two commits.

What changed

  • The key size is a subtype. Types.Key (K) is gone. Every K that stands for Cryptol's k is a Key_Size, a Natural with Static_Predicate => Key_Size in 128 | 192 | 256. Nk and Nr are Static functions with no Pre. (#73 item 1, #80, PR #82)
  • The {k} functions are one generic. W, KeyExpansion, Cipher, InvCipher, InvCipher_Prime, Split_Key, Encrypt and Decrypt moved into Spec.AES_K (formal K : Key_Size), with no K argument and no precondition. Spec.AES128/192/256 are library-level instances, as Main.cry's AES128 = AES`{128}. The ghost Spec.Dispatch selects an instance by a run-time K for the implementation, and its postconditions carry the old explicit-K formulas. (PR #82)
  • The bodies call a Cryptol prelude in SPARK. @@, foldl, @/head, join/split on bits and pmult at [8] x [8] are now instances of generics under spark/src/cryptol/. Five AES statements stay written out, each with a measured reason. Public functions and contracts did not change. (#75, PRs #83, #85)
  • Main.Bit_Index is range 0 .. 256, down from 0 .. 2 ** 127 - 1. (#68, PR #77)
  • SBox_Entries moved under Spec.SBox, so its slow proof's closure dropped from 17 source inputs to 10. Each row lemma is now split into an inverse lemma that names nothing of the S-box and an S-box lemma, which took its cold proof from 1148 s to 493 s. SBoxCorrect's statement did not change. (#70, PRs #79, #86)
  • No spec unit changed in #76 or #84. #76 removed the unused SPARKlib dependency (no change under spark/src). #84, the constant-time S-box, changed only AES.Impl and its FFI unit.

Types.cry's type constraint Key k = (fin k, k % 64 == 0, k / 64 >= 2, k / 64 <= 4) is now a subtype rather than a Boolean. The predicate lists the three values because it must be static (a static predicate cannot use mod, RM 3.2.4), and a Pure instance needs static bounds for AES_K's subtypes. Dispatch.Lemma_Key_Size proves the list equal to the Cryptol's clauses (shown below). Nk/Nr are Static for the same reason, and a static function cannot have a Pre, so the constraint moved into the parameter's subtype. (#73, #80, PR #82)

Folds, in full New Prelude

Afterspark/src/cryptol/foundation_spark-cryptol-folds.ads:1–62 · 4431a75
--  Cryptol's left fold over a sequence, `foldl : {n, a, b} (fin n) =>
--  (a -> b -> a) -> a -> [n]b -> a` (Cryptol.cry:1146). It is a primitive,
--  with no Cryptol body; the prelude documents it by example, `foldl (+) 0
--  [1,2,3] = ((0 + 1) + 2) + 3`: the function is applied to the
--  accumulator and each element in turn, from the first, so the outermost
--  application is to the last element. Foldl_Take states that by
--  recursion on the number of elements folded, `foldl f z (take`{N} xs) =
--  f (foldl f z (take`{N - 1} xs)) (xs @ (N - 1))`, and Foldl is the fold
--  of the whole sequence.
--
--  The recursion runs from the last element because that is how the
--  implementation layer runs a fold, one element at a time in a loop: its
--  invariant after N elements is the fold of the first N, and the next
--  step is the definition. The equivalent recursion from the first
--  element, `foldl f z ([x] # xs) = foldl f (f z x) xs`, is a theorem
--  about this one; nothing in the spec layers needs it yet.
--
--  For a fold whose function closes over other values, as SHA-2's step3
--  closes over the block, see Enumeration_Folds.
