# SHA-256: from NSA's Cryptol to proved SPARK

This page shows how the SPARK crate `foundation_spark` implements SHA-256
(FIPS 180-4) and how that implementation is tied to NSA's Cryptol
specification in `algorithms/SHA2/`. Every excerpt is quoted from the
repository at commit `6210b99`, with its file and line range.
HMAC-SHA-256 is built on top of this and has its own page,
[`hmac-sha-256.md`](hmac-sha-256.md).

There are three layers:

- **The spec layer** (`spark/src/sha2/`: `Foundation_Spark.SHA2`, `.Notation`,
  `.Functions`, `.Preprocessing`, the generic `.Main` and its instance
  `.SHA256`). Ghost SPARK that mirrors NSA's Cryptol declaration by
  declaration: the same names where Ada allows them, the same types, the same
  iteration structure. It is never run in production. It exists to be
  compared with the Cryptol and to be named in contracts.
- **The refinement layers** (`SHA256_Bytes`, `SHA256_Blocks`), also ghost.
  `SHA256_Bytes.Hash_Bytes` restates the spec's bit-level `Hash` over bytes
  and words, and `Lemma_Hash_Bytes` proves the two equal. `SHA256_Blocks`
  holds the facts about folding the compression over runs of blocks that a
  streaming hash needs.
- **The implementation layer** (`SHA256_Stream`). Ordinary executable SPARK:
  `Compress`, `Init`/`Update`/`Final`, `Hash` and `Hash_Chunked`. Their
  postconditions name the spec layer, and gnatprove proves them.

```text
               NSA Cryptol (algorithms/SHA2/*.cry)
                 ^                              ^
   FFI (testing) |  SAW (step: all inputs;      | SAW (step: all inputs;
                 |  hash: fixed lengths)        | hash: fixed lengths)
                 |                              | FFI (testing)
  spec layer (ghost SPARK)                      |
                 ^                              |
                 | gnatprove, all inputs:       |
                 | Lemma_Hash_Bytes             |
  SHA256_Bytes.Hash_Bytes (ghost, bytes)        |
                 ^                              |
                 | gnatprove, all inputs:       |
                 | Post, Lemma_Update,          |
                 | Lemma_Final                  |
  SHA256_Stream (executable) -------------------+
```

How each link is checked:

- **gnatprove** proves, for every input, that the executable code equals the
  spec layer: `Compress = Step`, and `Hash` and `Hash_Chunked` equal
  `Hash_Bytes`, which equals the spec's `Hash` on the message's bits. This is
  the only check that covers every message length (below 2 ** 61 bytes).
- **The FFI check** exports the SPARK functions (spec layer and executables)
  through C, calls them from Cryptol with `foreign`, and compares them with
  NSA's functions by random (`:check`) or exhaustive (`:exhaust`) testing.
  It is testing, not proof.
- **SAW** proves LLVM bitcode of the implementation, and separately of the
  spec layer, equal to NSA's Cryptol. The compression function is proved for
  all inputs; anything that takes a message only at fixed lengths.

## Reading the notation

Cryptol:

- `[n]` is a sequence of `n` bits (a word); `[n][w]` is `n` words of `w`
  bits. Bit 0 is the most significant.
- `x @ i` is element `i` of `x`, counting from 0. `a # b` concatenates.
- `foldl f z xs` folds left: `f (... (f (f z x0) x1) ...) xn`.
- `{n, w}` introduces type parameters; ``f`{3}`` supplies one. A
  *parameterized module* (a `parameter` block) gets its types and values when
  it is imported, like an Ada generic.
- `/^` and `%^` are ceiling division and "what to add to reach a multiple".

SPARK:

- `with Ghost` marks code that exists only for proof.
- An *expression function*, `function F (X : T) return T is (expr);`, has its
  body as its definition, which the provers see.
- `Pre` and `Post` are the precondition and postcondition. In a `Post`,
  `X'Old` is `X` on entry and `F'Result` is the result.
- `Subprogram_Variant => (Decreases => T)` says a recursion terminates
  because `T` decreases.
- `pragma Loop_Invariant (...)` states what holds at each loop iteration.

```ada
   --  The right shift operation, Cryptol's `SHR x = x >> `n`
   --  (Notation.cry:60, [FIPS-PUB-180-4 Section 3.2]). A right shift by
   --  n of a w-bit word is division by 2 ** n.
   --  @param X The word to shift.
```

</td></tr>

The type parameters `{n, w}` become the formals of the generic package
`Notation` (`N`, `Word_Size`, and a modular type `Word`). The constraint
`n < w` is checked at instantiation by `pragma Compile_Time_Error`
([`notation.ads:30-34`](../../src/sha2/foundation_spark-sha2-notation.ads#L30-L34)).
`ROTR` is written as FIPS defines it, a right shift or'ed with a left shift
by `w - n`, rather than with Cryptol's `>>>`; the source comment cites
Cryptol's own property `ROTRIsRightCircularShift` (Notation.cry:107), which
proves the two equal. `ROTL` and the Cryptol's examples and properties are
not mirrored: SHA-256 does not use `ROTL`, and properties are statements,
not functions
([`notation.ads:12-14`](../../src/sha2/foundation_spark-sha2-notation.ads#L12-L14)).
Where the Cryptol writes ``ROTR`{2} x``, `Functions` instantiates the generic
once per amount, `package By_2 is new Notation (2, 32, Unsigned_32);`, and
calls `By_2.ROTR (X)`
([`functions.ads:52-98`](../../src/sha2/foundation_spark-sha2-functions.ads#L52-L98),
twelve instances).

`Ch` and `Maj` have no type signature in the Cryptol, so they are polymorphic

the same shape

`Parity` is SHA-1's and is not mirrored.

### Functions and Preprocessing: the constants

The constants are copied word for word. `K_256 : [64][32]`
(Functions.cry:57-66) is `K_256 : constant Words_32 (0 .. 63)`
([`functions.ads:130-146`](../../src/sha2/foundation_spark-sha2-functions.ads#L130-L146)),
and `H0_256 : [8][32]` (Preprocessing.cry:81-90) is
`H0_256 : constant Words_32 (0 .. 7)`
([`preprocessing.ads:13-21`](../../src/sha2/foundation_spark-sha2-preprocessing.ads#L13-L21)).
`Words_32` is an array of `Unsigned_32` indexed from 0, as `@` is
([`foundation_spark-sha2.ads:16-19`](../../src/sha2/foundation_spark-sha2.ads#L16-L19)).
The FFI check compares both exhaustively (one test each, below). The
constants of SHA-1, SHA-224 and the SHA-512 family are not mirrored.
`pad` and `parse`, the rest of `Preprocessing.cry`, are in the generic `Main`
(below), because `parse` produces `Main`'s words
([`preprocessing.ads:3-6`](../../src/sha2/foundation_spark-sha2-preprocessing.ads#L3-L6)).

### Main: the parameters become generic formals

`Main.cry` is a parameterized module: SHA-224, SHA-256, SHA-384 and SHA-512
are all `Main` with different parameters. The SPARK mirrors it with a generic
package whose formals are those parameters, in the same order.

`d` and `w` are `Digest_Size` and `Word_Size`. Ada needs two types that the

that gnatprove proves at the instance's elaboration
([`main.ads:65-71`](../../src/sha2/foundation_spark-sha2-main.ads#L65-L71)).

The same case split and the same four terms. In the Cryptol, `W` is a local

`Pad`'s precondition does.

## The Cryptol prelude in SPARK

Cryptol's built-ins are stated once, as generics in `spark/src/cryptol/`, and
the spec instantiates them. SHA-256 uses `Folds`, `Enumeration_Folds`,
`Join_Split` (and through it `Words`), `Bit_Sequences` and `Numeric`.

`foldl` is a Cryptol primitive with no body; Cryptol documents it by the
example `foldl (+) 0 [1,2,3] = ((0 + 1) + 2) + 3`. The SPARK states it by
recursion from the last element. The round fold needs a variant whose
function takes an extra argument `E`, because `step3` closes over the block
`M` and Ada's generic formal functions are not closures:

<tr><th>SPARK prelude: <a href="../../src/cryptol/foundation_spark-cryptol-enumeration_folds.ads#L39-L46"><code>spark/src/cryptol/foundation_spark-cryptol-enumeration_folds.ads:39-46</code></a></th>
<th>SPARK spec instance: <a href="../../src/sha2/foundation_spark-sha2-main.ads#L170-L181"><code>spark/src/sha2/foundation_spark-sha2-main.ads:170-181</code></a></th></tr>

```ada
   function Foldl
     (E : Env; Z : Acc; From, To : Index'Base) return Acc
   is
     (if To <= From then Z else F (E, Foldl (E, Z, From, To - 1), To - 1))
   with
     Pre                =>
       From >= Index'First and then (To <= From or else To - 1 <= Index'Last),

```

</td><td>

```ada

     (Env => Block, Acc => Hash_Value, Index => Round, F => Step3);

   function Foldl_Step3
     (M : Block; H : Hash_Value; N : Natural) return Hash_Value
   is
     (Rounds.Foldl (M, H, 0, N))

```

</td></tr>

`Foldl (E, Z, From, To)` is `foldl f z [From ..< To]` with `f` closed over
`E`. `Foldl_Step3` takes the number of rounds `N` rather than always `Klen`,
so that the implementation's loop invariant can name the fold after `T`
rounds. Recursing from the last element is what makes that work: the fold of
`T + 1` rounds is, by definition, one `Step3` after the fold of `T`.

The block fold, `foldl step H0 M'`, is `Folds.Foldl_Take`
([`folds.ads:39-44`](../../src/cryptol/foundation_spark-cryptol-folds.ads#L39-L44),
``foldl f z (take`{N} xs)``), instantiated with `Step` as `Blocks` and
wrapped as `Foldl_Step`
([`main.ads:350-365`](../../src/sha2/foundation_spark-sha2-main.ads#L350-L365)).
`Numeric` states `/^` as `(A + (B - 1)) / B` and `%^` as
`Ceil_Div (A, B) * B - A`
([`numeric.ads:21-31`](../../src/cryptol/foundation_spark-cryptol-numeric.ads#L21-L31)).
`Join_Split` states `join` and `split` between words and bits
([`join_split.ads:44-89`](../../src/cryptol/foundation_spark-cryptol-join_split.ads#L44-L89)).

## The implementation and refinement layers

### `Compress`

`Compress` is the compression function, in place. Its postcondition is the
spec's `Step`:

```ada
   procedure Compress (H : in out SHA256.Hash_Value; M : SHA256.Block) with
     Post => H = SHA256.Step (H'Old, M);
```

([`spark/src/sha2/foundation_spark-sha2-sha256_stream.ads:53-54`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L53-L54))

The body computes the whole 64-word schedule into an array, then runs the 64
rounds. Its two loop invariants carry the proof. After iteration `T` of the
schedule loop, every word computed so far equals the spec's `W`:

```ada
         pragma Loop_Invariant
           (for all S in 0 .. T => Sched (S) = SHA256.W (M, S));
```

([`sha256_stream.adb:94-95`](../../src/sha2/foundation_spark-sha2-sha256_stream.adb#L94-L95))

After round `T`, the working variables equal the spec's fold of the first
`T + 1` rounds:

```ada
         pragma Loop_Invariant (V = SHA256.Foldl_Step3 (M, H, T + 1));
```

([`sha256_stream.adb:129`](../../src/sha2/foundation_spark-sha2-sha256_stream.adb#L129))

Each round only has to match `Step3` once. After the loop,
`V = Foldl_Step3 (M, H, 64)`, and `H + V` is `Step (H, M)`. At run time
`Compress` calls the spec's sigma functions, `Ch` and `Maj` directly: those
are executable, not ghost (see the last section).

### The streaming interface and `Hash`

A `Context` holds the hash value after the whole blocks seen so far, a
64-byte buffer, and a byte count. `Init`'s postcondition is
`Models (C, Empty) and then Count (C) = 0`
([`sha256_stream.ads:129-130`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L129-L130)).
`Update`'s postcondition `Absorbed` relates the new context to the old one and
the data:

```ada
   procedure Update (C : in out Context; Data : Byte_Array) with
     Pre  =>
       Count (C) < SHA256_Bytes.Max_Bytes
       and then Data'Length < SHA256_Bytes.Max_Bytes - Count (C),
     Post =>
       Absorbed (C'Old, Data, C)
       and then Count (C) = Count (C'Old) + Data'Length;
```

([`sha256_stream.ads:135-141`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L135-L141))

`Final`'s postcondition `Finished (C, Final'Result)` says the digest is the
context's hash value with `Step` folded over the padded buffer
([`sha256_stream.ads:160-162`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L160-L162)).
`Load_Block`, which reads 64 bytes as a block, has the postcondition
`Load_Block'Result = SHA256.Parse (SHA256_Bytes.Bits_Of (B (F .. F + 63)), 1) (0)`:
it is `parse` one block at a time
([`sha256_stream.ads:62-70`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L62-L70)).

The one-shot `Hash` names both the refinement layer and the spec:

```ada
   function Hash (M : Byte_Array) return Digest with
     Pre  => M'Length < SHA256_Bytes.Max_Bytes,
     Post =>
       Hash'Result = SHA256_Bytes.Hash_Bytes (M)
       and then SHA256_Bytes.Bits_Of (Hash'Result)
                = SHA256.Hash (SHA256_Bytes.Bits_Of (M));
```

([`sha256_stream.ads:214-219`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L214-L219))

`Hash_Chunked (M, Ends)` runs `Init`, an `Update` per chunk and `Final`, and
its postcondition is `Hash_Chunked'Result = SHA256_Bytes.Hash_Bytes (M)` for
every nondecreasing list of chunk ends
([`sha256_stream.ads:231-239`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L231-L239)):
the streaming theorem, for the chunks of one array.

### The byte-level refinement: `Hash_Bytes`

The spec works on bits; the implementation on bytes. `Hash_Bytes` is the
spec's computation written over bytes and big-endian words: pad to bytes
(`Pad_Bytes`), read the blocks (`Parse_Bytes`), fold the spec's own `Step`
from `H0`, write the result as bytes.

```ada
   function Hash_Bytes (M : Byte_Array) return Digest is
     (Digest_Bytes
        (SHA256.Foldl_Step
           (Preprocessing.H0_256,
            Parse_Bytes (Pad_Bytes (M), Blocks (M'Length)),
            Blocks (M'Length))))
   with
     Ghost,
     Pre => M'Length < Max_Bytes;
```

([`spark/src/sha2/foundation_spark-sha2-sha256_bytes.ads:200-208`](../../src/sha2/foundation_spark-sha2-sha256_bytes.ads#L200-L208))

It is not a Cryptol declaration, so it is not part of the spec layer. One
lemma links it to the spec:

```ada
   procedure Lemma_Hash_Bytes (M : Byte_Array) with
     Ghost,
     Pre  => M'Length < Max_Bytes,
     Post => Bits_Of (Hash_Bytes (M)) = SHA256.Hash (Bits_Of (M));
```

([`sha256_bytes.ads:425-428`](../../src/sha2/foundation_spark-sha2-sha256_bytes.ads#L425-L428))

Under it: `Lemma_Pad_Bytes` (the bits of `Pad_Bytes (M)` are
`SHA256.Pad (Bits_Of (M))`, lines 284-294), `Lemma_Parse_Bytes` (words read
big-endian from the padded bytes are the words `Parse` cuts from the padded
bits, lines 345-355), `Lemma_Digest_Bytes` (the digest bytes are
`take (join H)`, lines 371-373), and `Lemma_Pad`, which states `Pad` bit by
bit for any bit length, not only whole bytes (lines 231-247).

### Streaming: `Models`, `Lemma_Update`, `Lemma_Final`

A context does not hold the message, so the link from a context to the bytes
it has consumed is a ghost predicate, `Models (C, M)`: `C` has counted `M`'s
bytes, its hash value is `Step` folded from `H0` over `M`'s whole blocks, and
its buffer holds the bytes after them
([`sha256_stream.ads:99-108`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L99-L108)).
Two lemmas turn the contracts of `Update` and `Final` into statements about
the message:

```ada
   procedure Lemma_Update
     (C0 : Context; Data : Byte_Array; C1 : Context; M, M2 : Byte_Array)
   with
     Ghost,
     Pre  =>
       Data'Length < SHA256_Bytes.Max_Bytes
       and then M2'Length < SHA256_Bytes.Max_Bytes
       and then Models (C0, M)
       and then Absorbed (C0, Data, C1)
       and then M2'Length = M'Length + Data'Length
       and then
         (for all I in 0 .. SHA256_Bytes.Byte_Index (M'Length) - 1 =>
            M2 (M2'First + I) = M (M'First + I))
       and then
         (for all I in 0 .. SHA256_Bytes.Byte_Index (Data'Length) - 1 =>
            M2 (M2'First + SHA256_Bytes.Byte_Index (M'Length) + I)
            = Data (Data'First + I)),
     Post => Models (C1, M2);
```

([`sha256_stream.ads:172-189`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L172-L189))

```ada
   procedure Lemma_Final (C : Context; M : Byte_Array) with
     Ghost,
     Pre  => Models (C, M),
     Post => Count (C) < SHA256_Bytes.Max_Bytes
             and then Final (C) = SHA256_Bytes.Hash_Bytes (M);
```

([`sha256_stream.ads:201-205`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L201-L205))

`Lemma_Update`: if `C0` is the context after `M`, and `C1` is `C0` after
`Data`, then `C1` is the context after `M` followed by `Data` (`M2`).
`Lemma_Final`: the digest of the context after `M` is `Hash_Bytes (M)`. Their
proofs use `SHA256_Blocks`: `Fold_Blocks` folds `Step` over `K` blocks of a
byte array from any offset
([`sha256_blocks.ads:72-85`](../../src/sha2/foundation_spark-sha2-sha256_blocks.ads#L72-L85)),
`Lemma_Fold_Split` says folding `A + B` blocks is folding `A` and then `B`
([`:158-176`](../../src/sha2/foundation_spark-sha2-sha256_blocks.ads#L158-L176)),
and `Lemma_Fold_Ext` and `Lemma_Foldl_Parse` compare folds over equal bytes
and relate `Fold_Blocks` to `Hash_Bytes`'s `Foldl_Step`
([`:129-146`](../../src/sha2/foundation_spark-sha2-sha256_blocks.ads#L129-L146),
[`:187-198`](../../src/sha2/foundation_spark-sha2-sha256_blocks.ads#L187-L198)).
The extensionality lemmas are needed because Ada's array `=` is not the
provers' logical equality
([`sha256_blocks.ads:18-20`](../../src/sha2/foundation_spark-sha2-sha256_blocks.ads#L18-L20)).

The one-shot `Hash` shows the whole chain:

```ada
   function Hash (M : Byte_Array) return Digest is
      C : Context;
   begin
      Init (C);
      declare
         C0 : constant Context := C with Ghost;
      begin
         Update (C, M);
         Lemma_Update (C0, M, C, Empty, M);
      end;
      Lemma_Final (C, M);
      Lemma_Hash_Bytes (M);
      return Final (C);
   end Hash;
```

([`sha256_stream.adb:411-424`](../../src/sha2/foundation_spark-sha2-sha256_stream.adb#L411-L424))

`Init` gives `Models (C, Empty)`. `Update` and `Lemma_Update` give
`Models (C, M)`. `Lemma_Final` gives `Final (C) = Hash_Bytes (M)`.
`Lemma_Hash_Bytes` gives `Bits_Of (Hash_Bytes (M)) = SHA256.Hash (Bits_Of (M))`.
Together they are `Hash`'s postcondition. `Hash_Chunked` does the same with
`Models (C, M (M'First .. M'First + Done - 1))` as its loop invariant
([`sha256_stream.adb:440`](../../src/sha2/foundation_spark-sha2-sha256_stream.adb#L440)).
No executable code calls ghost code: `Step`, `Hash_Bytes` and the folds
appear only in contracts, assertions and lemmas
([`sha256_stream.ads:29-31`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L29-L31)).

## How it is checked

### gnatprove: every input

gnatprove proves the contracts above for every input: `Compress` for every
hash value and block; `Hash`, `Init`, `Update` and `Final` for every message
below 2 ** 61 bytes (`Max_Bytes`,
[`sha256_bytes.ads:52`](../../src/sha2/foundation_spark-sha2-sha256_bytes.ads#L52));
`Hash_Chunked` for every message and every chunking; and the lemmas. It does
not compare anything with NSA's Cryptol. That is what the next two checks do.

### The FFI check: testing against the Cryptol

`spark/scripts/check-ffi.sh` builds the crate as a shared library. Cryptol
modules under `spark/cryptol/SPARK/SHA2/` declare its exports as `foreign`
functions with no Cryptol body and compare them with NSA's functions. Two
representative properties:


### SAW: proof against the Cryptol at fixed sizes

SAW proves LLVM bitcode equal to NSA's Cryptol, imported unmodified. Two
small Cryptol files of ours stand between. `spark/saw/SHA256Main.cry`
instantiates `Main` with `SHA256.cry`'s parameters, because `SHA256.cry`'s
instance is private and SAW 1.6 cannot load `packaging/Hash.cry`
([`SHA256Main.cry:1-11`](../../saw/SHA256Main.cry#L1-L11)).
`spark/saw/SHA256Step.cry` copies `step`'s locals `W`, `T1`, `T2` and `step3`
out of `step`, text for text, so that they can be named
([`SHA256Step.cry:1-15`](../../saw/SHA256Step.cry#L1-L15)). The spec's `Step`
is then proved against NSA's `step` itself, which ties the copies to
`Main.cry`.

The record is [`spark/saw/results.txt`](../../saw/results.txt) (the default
run) and [`spark/saw/results-long.txt`](../../saw/results-long.txt) (with
`SAW_LONG=1`), both made at commit `82b10e6` (results.txt:9).

- **Implementation** (`spark/saw/sha256_impl.saw`, `sha256_impl_common.saw`).
  `SHA256_Stream.Compress` equals `Main.cry`'s `step` for **all** hash values
  and blocks (results.txt:182). `SHA256_Stream.Hash` equals `hash` at 12
  message lengths: 0, 1, 55, 56, 63, 64, 65, 100, 119, 120, 128 and 200 bytes
  (results.txt:203-214). `Init`, `Update`, `Final`, `Load_Block` and
  `To_Digest` are executed within those proofs, not proved on their own.
  `Hash_Chunked` is not proved by SAW: its claim is about every chunking.
- **Spec layer** (`spark/saw/sha256_spec.saw`, with `sha256_spec_step.saw`,
  `sha256_spec_pad.saw`, `sha256_spec_hash.saw`, `sha256_spec_prelude.saw`
  and `sha256_spec_common.saw`). The spec's `Step` equals `step` for all
  inputs (results.txt:800), with `W` proved index by index below it (from
  results.txt:604). `Pad` equals `pad` at the same twelve lengths (for
  example results.txt:1077, at 0 bits). `Hash` equals `hash` at 0, 1, 55, 56,
  63, 64, 65, 100 and 119 bytes in the default run (for example
  results.txt:1078 and 1081), and also at 120, 128 and 200 bytes with
  `SAW_LONG=1` (results-long.txt:1178, 1154 and 1193). `Parse` equals `parse`
  at 1 and 2 blocks (results.txt:1072-1073).
- **Negative controls**: deliberately broken variants of `Compress`, `Hash`,
  `Step`, `W`, `Pad` and `Parse` fail with a counterexample, as they must
  (`spark/saw/negative/`; the `negative` lines near the end of results.txt).

The default run took 32 s for `sha256_impl.saw` and 1385 s for
`sha256_spec.saw` (results.txt:1239).

### What is proved for all inputs, and what is not

- **Proved for all inputs, by gnatprove**: the executable `Compress`, `Hash`,
  `Hash_Chunked` and streaming interface equal the spec layer, for every
  message below 2 ** 61 bytes and every chunking.
- **Proved for all inputs, by SAW**: `Compress` and the spec's `Step` equal
  NSA's `step`; the spec's sigma functions, `Ch` and `Maj` equal NSA's.
- **Proved at fixed lengths only, by SAW**: the executable `Hash`, and the
  spec's `Pad`, `Parse` and `Hash`, equal NSA's at the lengths listed.
- **Tested only, by the FFI check**: the spec layer against NSA's Cryptol at
  all other lengths, and `Hash_Bytes`, which no SAW proof covers (gnatprove
  proves it equal to the spec's `Hash` instead).

So "spec = Cryptol" is a proof at the sizes SAW covers and evidence by
testing elsewhere; "implementation = spec" is a proof for every input.

## Where spec and implementation are not one-to-one

[The section of this name in proving.md](../proving.md#where-spec-and-implementation-are-not-one-to-one) lists the places where
there is not one executable function per spec function, by design. For
SHA-256:

- **`pad` is subsumed by `hash`.** There is no executable `Pad`. A streaming
  hash never builds the padded message, which would cost a copy of the whole
  message. `Final` writes only the last one or two padded blocks
  (`Tail_Pad`,
  [`sha256_stream.ads:274-288`](../../src/sha2/foundation_spark-sha2-sha256_stream.ads#L274-L288)),
  and `Lemma_Final` proves them the last blocks of `Pad (M)`. `Hash`'s
  postcondition is the spec's `Hash`, which is defined through `Pad`, so the
  padding is covered. `Pad` itself is FFI-checked (`prop_pad`) and
  SAW-proved at the spec layer.
- **`Ch`, `Maj` and the four sigma functions are their own implementation.**
  They are on `Unsigned_32` with no change of representation, so the spec
  functions are executable and `Compress` calls them. A second copy would add
  a name, not a proof.
- **`hash` over bytes.** `SHA256_Stream.Hash` is proved equal to
  `SHA256_Bytes.Hash_Bytes`, and through `Lemma_Hash_Bytes` to the spec's
  `Hash` on the message's bits. `Hash_Bytes` is a representation layer, not a
  Cryptol declaration; the byte-level FFI properties reach `hash` through it.
- **`parse`** has an executable counterpart one block at a time,
  `Load_Block`, whose postcondition is the spec's `Parse` with `N = 1`.
