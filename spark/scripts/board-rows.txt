# board-rows.txt -- the rows of the campaign's board, read by scripts/board.py.
#
# One line per function the campaign promises, which makes this file the
# board's denominator:
#
#     function | spec entity | impl entity [| kind]
#
# function     The Cryptol declaration, qualified by its module as the .cry
#              file names it (AES::GF28::xTimes, SHA2::Main::step). The FFI
#              log (README "The board") names its properties' functions the
#              same way, which is how a row finds its FFI results.
# spec entity  The spec-layer Ada entity that mirrors it, fully qualified, as
#              gnatprove names it in its .spark files
#              (Foundation_Spark.AES.Spec.GF28.xTimes). For a generic, name the
#              entity of the instance that is proved
#              (Foundation_Spark.SHA2.SHA256.Step), not the generic's.
# impl entity  The implementation entity proved equal to the spec, likewise;
#              `-` until it exists, or for a row that has none by design.
# kind         How the row is complete (#67; README "Where spec and
#              implementation are not one-to-one"). Optional: a row without
#              a fourth field is `impl`.
#                impl          the default: the spec is FFI-checked, and the
#                              impl entity is proved equal to it.
#                impl = spec   the spec function is executable, and is the
#                              implementation: the impl entity is the spec
#                              entity.
#                spec-only E...  no implementation, by design: complete when
#                              the spec's unit is proved and so is each
#                              entity E (the proofs that tie the spec to the
#                              implementation). No FFI property is needed.
#                subsumed-by F   no implementation, by design: complete when
#                              the spec is FFI-checked and row F (a function
#                              of this file) is complete, F's proof being
#                              the proof of this row's spec.
#
# The spec and the implementation of one function live in different units, so
# a row names both. A tick that adds a spec-layer function adds its row here in
# the same PR; the tick that adds the implementation fills in the third field.
# A name that matches no .spark entity shows as "no" on the board (not built
# yet, or misspelled: the board says which entity it looked for).

# AES (#11) fills the impl column of every AES row below but Main's: the
# entities of Foundation_Spark.AES.Impl, each with a postcondition of equality
# with the row's spec entity. Main.cry's Encrypt and Decrypt are over bits;
# their impl entities are AES.Impl.Main's Encrypt and Decrypt over bytes,
# whose postconditions state that the bits of the result are the spec's
# Encrypt or Decrypt of the bits of the key and the block. Expand_Key,
# Encrypt_Block, Decrypt_Block and Decrypt_Block_Prime are also exported and
# FFI-checked (FFI.AES_Impl), against the KeyExpansion, Cipher, InvCipher and
# InvCipher' rows' functions and, composed, against Main's Encrypt and
# Decrypt; their properties count towards those rows' FFI column.

# SHA-2 (#14): Functions.cry and Main.cry's step, through the SHA-256
# instance of the generic Main (Ch and Maj are its instance of Logical).
#
# The Functions rows' impl entity is the spec entity itself. Functions.cry's
# Ch, Maj, SIGMA_256_0/1 and sigma_256_0/1 are functions on [32], which the
# spec layer states on Unsigned_32 with no change of representation, so the
# spec functions are not ghost: they are executable, and they are what
# SHA256_Stream.Compress calls at run time for every round and schedule
# word. There is no other implementation of them to prove equal, and a
# wrapper that only called them would add a name, not a proof. Their kind
# is impl = spec (#67).

SHA2::Functions::Maj          | Foundation_Spark.SHA2.SHA256.Logical.Maj            | Foundation_Spark.SHA2.SHA256.Logical.Maj | impl = spec
SHA2::Functions::SIGMA_256_0  | Foundation_Spark.SHA2.Functions.SIGMA_256_0         | Foundation_Spark.SHA2.Functions.SIGMA_256_0 | impl = spec

# SHA-2 (#15): Preprocessing.cry's pad and parse (stated in the generic Main,
# whose formals fix w) and Main.cry's hash, through the SHA-256 instance.
#
# parse's impl is SHA256_Stream.Load_Block, which parses one block of bytes
# into words: its postcondition is the spec's Parse of the 64 bytes' bits at
# N = 1 (SHA256_Blocks.Lemma_Block_Parse). The streaming hash parses each
# block with it as it reaches it. pad has no executable counterpart of its
# own: the stream never builds the padded message, and SHA256_Stream.Final
# writes only its last one or two blocks (Tail_Pad), whose correctness is
# part of Lemma_Final and so of Hash's proof: its kind is subsumed-by the
# hash row (#67), whose impl's postcondition is the spec's Hash, defined
# through Pad.
SHA2::Preprocessing::pad (SHA-256)   | Foundation_Spark.SHA2.SHA256.Pad     | - | subsumed-by SHA2::Main::hash (SHA-256)
SHA2::Preprocessing::parse (SHA-256) | Foundation_Spark.SHA2.SHA256.Parse   | Foundation_Spark.SHA2.SHA256_Stream.Load_Block
SHA2::Main::hash (SHA-256)    | Foundation_Spark.SHA2.SHA256.Hash                   | Foundation_Spark.SHA2.SHA256_Stream.Hash

# SHA-2 (#16): the byte-level refinement of hash at SHA-256. Hash_Bytes is not
# a Cryptol declaration: it is SHA256::hash over a message of whole bytes,
# proved equal to SHA256.Hash on their bits (Lemma_Hash_Bytes). Its FFI check
# is against SHA256::hash through a byte-packing wrapper; M2.4 (#17) fills in
# the implementation.
SHA2::Main::hash (SHA-256, bytes) | Foundation_Spark.SHA2.SHA256_Bytes.Hash_Bytes | Foundation_Spark.SHA2.SHA256_Stream.Hash

# SHA-2 (#17): the implementation, SHA256_Stream, fills the impl column of the
# step and hash rows above. Compress is proved equal to Step. Hash, the
# one-shot hash (Init, one Update, Final), is proved equal to Hash_Bytes and to
# SHA256.Hash on the bits. The streaming interface is proved through
# Lemma_Update and Lemma_Final, and Hash_Chunked states it for every chunking
# of an array; it adds no row, since it is the same function as hash (bytes).

# HMAC (#19): HMAC/Main.cry's HMAC and HMAC_init (private in the Cryptol),
# through the SHA-256 instance of the generic Main, as packaging/Hash.cry
# instantiates them for SHA256.cry. M3.2 (#20) fills in the implementation:
# SHA256_Impl.HMAC_SHA256 (bytes, λ = 256, over two SHA256_Stream contexts)
# and SHA256_Impl.Init_Key (K0), each proved equal to the spec on the bits.
# The incremental Init/Update/Final is the same function and adds no row.
HMAC::Main::HMAC (SHA-256)      | Foundation_Spark.HMAC.SHA256.HMAC                 | Foundation_Spark.HMAC.SHA256_Impl.HMAC_SHA256
HMAC::Main::HMAC_init (SHA-256) | Foundation_Spark.HMAC.SHA256.HMAC_init            | Foundation_Spark.HMAC.SHA256_Impl.Init_Key
